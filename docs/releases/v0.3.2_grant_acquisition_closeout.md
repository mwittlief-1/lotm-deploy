Epic: `V03-R2-006`

## Scope

This closeout records the accepted `v0.3.2` grant and acquisition baseline
after `T01` through `T05`. It supersedes the opening audit as the current
release-facing summary of what the grant and acquisition seam now guarantees,
which invariants are locked, and what later integrator, clergy, and agenda
work may safely assume.

## Accepted task sequence

- `T01` audited the live acquisition surfaces and confirmed that grant logic
  was still phase-owned and arrears-only while marriage and inheritance
  already had people-domain seams.
- `T02` defined the canonical grant source registry, grant dossier summary,
  and acquisition-window schema contracts.
- `T03` locked explicit grant eligibility rules around liege favor, ledger
  standing, and portfolio capacity.
- `T04` added deterministic liege-demesne and dispossessed-pool source
  registries using bounded world and portfolio inputs.
- `T05` projected marriage, grant, and inheritance claim prospects through a
  single canonical acquisition window and exposed that window on preview and
  bounded snapshot surfaces.

## Locked `v0.3.2` grant rules

### Grant eligibility is explicit now

The grant seam now evaluates three rule families directly:

- liege favor, read from the canonical relationship engine surface
- ledger tolerance, using bounded current-due and arrears thresholds
- manor-capacity headroom, using the existing portfolio placeholder contract

The accepted baseline now treats a grant as blocked when any of the following
are true:

- liege favor is below the grant threshold
- current dues are above the grant tolerance
- arrears are above the grant tolerance
- the portfolio is already at capacity

That gives later work a reusable contract instead of repeating ad hoc checks in
phase logic or UI code.

### Grant sources are bounded and replay-safe

The new source registry now exposes two explicit origin types:

- `liege_demesne`
- `dispossessed_pool`

The accepted baseline uses:

- crown-domain world records for liege demesne candidates
- nearby non-church mesne holdings as the bounded dispossessed-pool proxy

This is intentionally a seam, not a final feudal-title simulation. The actor
bridge between the bundled world files and runtime local titles still does not
exist, so the source registry is best understood as a deterministic proxy layer
that later integrator work can adopt or refine.

### Dossiers stay coarse by design

Grant dossiers are intentionally limited to:

- source identity and origin type
- coarse holding labels
- coarse distance band
- liege relationship band
- ledger band
- capacity band
- manor-count hint
- kinship summary

That keeps the snapshot safe while still giving downstream consumers enough
material to explain why a grant is present.

## Locked `v0.3.2` acquisition rules

### Marriage, grant, and inheritance now share one bounded ordering seam

The accepted baseline now exposes a canonical
`acquisition_prospects_window_v0` that:

- rebuilds marriage, grant, and inheritance claim prospects from domain-owned
  builders
- applies one deterministic ordering rule across the three prospect families
- stays bounded to the canonical acquisition window only

The locked acquisition order is:

1. marriage
2. grant
3. inheritance claim

with deterministic tie-breaking inside each family.

### Preview and snapshot surfaces now expose the canonical window

The following hidden-but-readable surfaces are now attached to both preview
state and bounded snapshots:

- `grant_eligibility`
- `grant_source_registry`
- `grant_dossier_summaries`
- `acquisition_prospects_window`

These remain non-enumerable on bounded snapshots, which preserves the existing
serialized replay contract while still giving later consumers a canonical
surface to read directly.

## Explicit `v0.3` non-goals

The accepted grant baseline intentionally does **not** include:

- edits to `src/sim/phases/phase_prospects.ts`
- new accept or reject runtime behavior for grants
- direct title binding between runtime liege actors and world crown holders
- multi-turn external-house dispossession simulation
- agenda or clergy mechanics sourced directly from grant state

Those remain later backlog work, not missing pieces inside this epic.

## Handoff to later work

Later integrator and content work may now treat the following as locked inputs:

- grant eligibility has explicit threshold semantics
- grant source origin types are stable and bounded
- grant dossiers expose coarse, snapshot-safe explanation fields
- marriage, grant, and inheritance claim prospects can be read from one
  canonical acquisition window on preview and bounded snapshot surfaces

Later work should not assume the following already exist:

- live phase adoption of the new grant registry
- runtime title-to-world source fidelity beyond the current proxy layer
- AI or agenda systems consuming grant sources directly
