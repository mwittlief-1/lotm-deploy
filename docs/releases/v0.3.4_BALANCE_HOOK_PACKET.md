- Central tuning table: `src/sim/domains/economy/tuningTable.ts`

## DOE and KPI expectations

The accepted DOE harness is for deterministic review, not automatic retuning.

The canonical 15-turn slice currently establishes these expectations:

- no dispossession occurs in either policy pack
- manor-count distribution remains fixed at `1`
- builder-forward shows arrears in every sampled run
- prudent-builder still shows some arrears and food pressure, but ends materially stronger than builder-forward on stores
- mean ending meat stores remain `0`, so meat is still a pressure indicator rather than a durable reserve in the shipped baseline

The builder-forward 30-turn slice exists because the canonical 15-turn slice does not reach dispossession. In the current accepted baseline it shows:

- dispossession rate `0.375`
- median game-over turn `26`
- manor-count distribution still fixed at `1`

These values are not targets. They are the accepted reference points future balancing should compare against before changing knob values.

## Review flow

When later balance work adjusts fiscal knobs, review should proceed in this order:

1. confirm the tuning table hash changes intentionally
2. rerun the DOE harness and compare the 15-turn and 30-turn summary hashes
3. rerun the regression seed pack and inspect the four canonical scenarios first
4. reject the change if replay hash, ordering, or deterministic artifact shape shifts unexpectedly

Later work should extend the existing tuning table, DOE harness, and regression seed pack. It should not introduce a second balance configuration surface or a parallel seed-selection contract.
