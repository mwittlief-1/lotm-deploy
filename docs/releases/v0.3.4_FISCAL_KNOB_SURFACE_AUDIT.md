# v0.3.4 Fiscal Knob Surface Audit

**Last Updated:** 2026-04-05
**Owner:** Economy / Fiscal lane
**Task:** `V03-R4-002-T01`

This document is the release-facing audit for the `v0.3.4` economy balance tranche. It inventories the currently shipped fiscal tuning surfaces, calls out the hidden constants that still live outside an economy-owned balance table, and defines the extraction targets for `V03-R4-002-T02` through `V03-R4-002-T05`.

## Scope

This audit covers lane-owned fiscal balance surfaces under:

- `src/sim/domains/economy/**`
- `tests/**`
- `docs/releases/**`

It does not change phase ordering or integrator wiring. Where current balance inputs still come from legacy shared modules or content flags, this audit records them as hidden dependencies rather than treating them as economy-owned knobs already.

## Current baseline

The fiscal spine now has explicit economy-domain seams for:

- obligations and arrears registry state
- stage-one and stage-two enforcement summaries
- food and meat production / consumption accounting
- fixed-ratio pricing references
- multi-manor portfolio rollups and outlier analysis

What it does not have yet is one central, versioned tuning table that owns the numeric balance inputs across those seams. Several numbers are still embedded directly in domain modules or imported from older shared constants.

## Hidden constants that still bypass a fiscal tuning table

The main hidden constants still bypassing a central economy table are:

- `src/sim/constants.ts`
  - `TURN_YEARS = 3`
  - `BUSHELS_PER_PERSON_PER_YEAR = 12`
  - `BUILDER_EXTRA_BUSHELS_PER_YEAR = 1`
  - `UNREST_BASELINE_DECAY_WHEN_STABLE = 2`
- `src/content/events.ts`
  - trade modifier flags such as `market_price_mult` and `sell_cap_mult`
  - ad hoc maintenance-like coin drains such as `evt_repair_bridge`

These values are deterministic today, but they are not yet economy-owned balance hooks. That is the gap `V03-R4-002-T02` should close for the lane-owned seams without editing integrator-owned phase orchestration.

## What is already safe to centralize

The current lane already owns and can safely move these values into one deterministic table:

- obligation settlement cadence
- stage-one obligation pressure deltas
- stable no-shortage / no-arrears unrest relief
- fixed price ratios and sell-cap basis points
- meat target basis points
- hunting yield divisors and martial threshold
- mirrored copies of current per-turn food-demand constants used by economy-domain consumption helpers

The following surfaces should be represented as placeholders or documented hook entries rather than activated new mechanics:

- default stage-two seizure / forced-payment caps
- maintenance scaling
- manor-count admin overhead scaling
- delegation-efficiency scaling
- active event-driven maintenance prices

## Summary

The fiscal spine is already structurally explicit enough for balance work, but its numeric control surface is still split across:

- hardcoded economy-domain values
- legacy shared constants
- phase / content-level trade modifiers
- documented-but-not-yet-live maintenance placeholders

`V03-R4-002-T02` should centralize the first three where lane scope allows, and represent the fourth as explicit placeholder hooks so later tuning work starts from one authoritative table instead of another round of audit-by-search.
