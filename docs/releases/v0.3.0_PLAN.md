# v0.3.0 PLAN — Refactor Kickoff + Parallel Workstream Enablement
**Last Updated:** 2026-03-23  
**Owner:** Integrator / Build Engineer

Authoritative update:
- `docs/releases/v0.3_SCOPE_LOCK.md` overrides this document on product scope conflicts.
- `ops/v0.3/*` is the canonical unattended execution contract.

## Goal
Create the minimum refactor, branch, and repo structure required for `v0.3` feature work to proceed in parallel across the eight product categories without destabilizing `v0.2final`.

## Non-Goals
- No big-bang gameplay rewrite.
- No broad duplicate-file deletion pass before canonical files are marked.
- No new feature activation beyond what is needed to establish seams and guardrails.

## Branch and Repo Strategy
1. Preserve `codex/v0.2final` as the release-hardening branch.
2. Use `codex/v0.3-refactor-kickoff` as the integrator branch for seam carving and repo strategy work.
3. Cut short-lived lane branches from the kickoff branch only after the prerequisite seam exists.
4. Merge lane branches back into the kickoff branch, not directly into `codex/v0.2final`.
5. Treat unsuffixed files as canonical active files until the cleanup tranche says otherwise.

## Delivery Model
### Tranche 0 — Rails
- Add `AGENTS.md`, charter, codemap, and kickoff plan.
- Create directory scaffolds for phases/domains/UI panels.
- Freeze duplicate-file policy.

### Tranche 1 — Baseline Verification
- Run QA/preflight on the kickoff branch.
- Confirm branch is clean and suitable as the new base for lane work.

### Tranche 2 — Phase Extraction
- Reduce `src/sim/turn.ts` to orchestration.
- Create thin phase wrappers with no intended behavior changes.

### Tranche 3 — Ownership Seams
- Centralize relationship writes.
- Start ledger-centric economy seams.
- Prepare bounded marriage ownership.

### Tranche 4 — UI Split
- Break `src/App.tsx` into panels and view models.
- Keep UI read-only relative to sim state mutations.

## Category-to-Code Ownership Map
- Simulation Core & Reliability: `src/sim/turn.ts`, `src/sim/phases/*`, migrations, QA harness, preflight
- People / Kinship / Dynasty: `src/sim/domains/people/*`, kinship, marriage, claims, succession helpers
- Economy / Fiscal Spine: `src/sim/domains/economy/*`, receipts, obligations, portfolio accounting
- CourtOS / Roles / Pacing: `src/sim/domains/court/*`
- World Model / Geography: `src/sim/domains/world/*`
- Realm Politics / Church / External Pressure: `src/sim/domains/realm/*`
- AI / Intel / Uncertainty: `src/sim/domains/ai/*`
- Experience Layer / UI / Content Ops: `src/ui/panels/*`, `src/sim/domains/experience/*`, content/readability work

## Gates
- `npm run qa`
- `npm run preflight`
- `npm run seed:replay:batch` twice with matching output once the replay harness is added

## Exit Criteria for Kickoff
- Repo contains the operating guardrails in canonical docs.
- The working branch strategy is in place and understandable.
- Phase/domain/UI panel scaffolds exist in the codebase.
- The repo remains green on baseline verification.
