## Findings
1. Grain-store mutation ownership is already partially centralized: runtime grain and coin deltas in active code paths mostly route through `src/sim/domains/economy/ledger.ts` instead of raw `state.manor` writes.
2. The fiscal packet name `food_stores` currently maps to `manor.bushels_stored`. That naming mismatch is harmless for replay today but blocks a clean multi-asset ledger contract.
3. `meat_stores` is absent from `RunState`, normalization, reports, fixtures, and tests. The codebase has no dormant meat seam to extract.
4. Hunting is absent from deterministic production sources, RNG keys, phase outputs, and receipts. This is a new production registry task, not a receipt-only follow-up.
5. Consumption is explicit and deterministic, but it is single-asset grain consumption. Court demand and peasant demand reconcile cleanly, yet both drain the same grain store.
6. Receipt ownership is still too coarse for the fiscal packet. The turn pipeline emits phase summaries and notes, not ordered receipt lines keyed by asset, category, counterparty, and delta.

## Closed assumptions handed forward
- `coin`, `food_stores`, and `meat_stores` are the first-class fiscal assets for downstream economy work, with `food_stores` still meaning the legacy grain-store balance.
- Hunting is no longer a hypothetical packet note; it is a deterministic production source with a stable formula and stable output registry ordering.
- Food and meat mutations have canonical economy-owned receipt writers and settlement scaffolds, so downstream obligations work should extend those helpers instead of reintroducing ad hoc phase-summary ownership.
- Food and meat equilibrium review now has a fixed-seed artifact, so future tuning can be judged against a known balanced/reserve/scarcity baseline.
