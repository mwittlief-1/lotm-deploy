# v0.3.3 Realm Pressure Surface Audit (V03-R3-005-T01)

**Last Updated:** 2026-04-04
**Owner:** Engine / Realm lane
**Reference Packet:** `docs/releases/v0.3_SCOPE_LOCK.md`

This audit inventories the live liege, church, and magnate-adjacent
pressure surfaces that exist before `V03-R3-005-T02` introduces a typed
realm-pressure registry and read-only political-weather schema. It is
descriptive only. No live political behavior changes are made here.

## Scope lock carried into political weather

- `v0.3` realm politics remains scaffolding-only.
- Church and liege already exist as obligation counterparties and
  relationship targets.
- `v0.3.3` adds surfaced political-weather fields; it does not activate
  new pressure mechanics.
- `src/sim/domains/README.md` already lists `realm` as a planned domain,
  but no `src/sim/domains/realm/**` runtime surface exists yet on this
  branch.

## Findings

1. The repo already contains meaningful political pressure signals, but they are split across economy obligations, people relationships, event weights, and phase-owned prose rather than gathered under a realm-domain seam.
2. Liege and church have live durable pressure inputs today because obligations and enforcement already model named counterparties. Magnates do not; they only have social-summary precursors in `known_houses`, `house_dossiers`, and seeded local-house relationships.
3. The current grant path is still a fiscal-pressure proxy, not a relationship-aware political system. It reacts to arrears and applies fixed liege deltas instead of reading seeded liege affinity or any realm-weather registry.
4. Church targeting remains intentionally split: obligation and enforcement pressure points at `locals.clergy`, while world init separately exposes a parish institution. That split should be carried forward explicitly until clergy-placement and institution-holder tasks close it.
5. Current exports and bounded snapshots still have no `political_weather` or realm-pressure surface, so later content and UI work would have to infer politics from arrears, unrest, and relationship edges if `T02` through `T04` do not add a read-only contract.

## Task-to-task handoff

- `V03-R3-005-T02` should define the minimal read-only realm-pressure registry around the live precursors already identified here: liege/church obligation pressure, local-house relationship surfaces, and shared unrest/shortage context. That task should stay descriptive and deterministic.
- `V03-R3-005-T03` should seed bounded crown, magnate, and church latent baselines from current state without activating new mechanics or perturbing replay ordering.
- `V03-R3-005-T04` should expose snapshot and content-hook outputs so UI and event code can consume political weather directly instead of inferring it from arrears or relationship edges.
- `V03-R3-005-T05` can then add fixtures and closeout docs once the schema and exposure surfaces are stable.
