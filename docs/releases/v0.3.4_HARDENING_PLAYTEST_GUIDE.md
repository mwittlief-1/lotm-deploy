## 2. Intentional accepted diffs

These behaviors changed intentionally during hardening and should now be treated as the correct baseline:

- widowed heads can re-enter the marriage path when no living spouse remains
- stale dead-spouse edges no longer block remarriage eligibility
- canonical heir selection no longer trusts a stale persisted `house.heir_id`
- inheritance-claim suppression now reopens when a stale non-canonical heir pointer is repaired away
- succession spouse selection ignores ended spouse edges and keeps the active living spouse

If a tester sees the old behavior instead, that is a bug relative to the accepted `v0.3.4` line, not a design ambiguity.

## 3. What playtesters should target

Prioritize packets and bug reports around these surfaces:

1. widowhood transition
   - spouse death produces one clear survivor/deceased interpretation
   - roster and court surfaces agree on widow or widower badges
2. remarriage recovery
   - widowed subjects can receive or accept valid remarriage paths
   - stale dead-spouse edges do not silently lock marriage paths
3. succession graph integrity
   - exactly one current heir path is surfaced
   - succession does not promote the wrong spouse because of duplicate or ended edges
4. inheritance-claim suppression
   - claims appear when the canonical line is genuinely empty
   - claims do not appear when a real canonical heir still exists

## 4. Remaining known limitations

These are still accepted limits, not new bugs by themselves:

- playtest packet assembly is still manual
- packet exports still carry `app_version: v0.2.9` inside run summary JSON on this branch line
- KPI snapshots are placeholders, not measured dashboards
- family-graph hardening is targeted; it is not a full inheritance-system redesign
- replay batches may still emit accepted soft time-ceiling warnings during long seed runs

## 5. Filing rules

- File one issue per distinct bug class.
- Treat widowhood, remarriage, succession, and inheritance-claim problems as separate reports unless they are clearly the same root failure in one packet.
- Include the replay hash and exact reviewed artifacts in every report.
