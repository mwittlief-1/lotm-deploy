## Scope

This audit records the current world-init surfaces that seed relationship edges, known houses, kinship, and church-adjacent actors, then compares that baseline to the `v0.3` scope lock and fiscal spine contracts.

## Current seeding surfaces

### 1. `createNewRun` seeds the starter actors and the first relationship edges

`src/sim/state.ts` creates:

- the player household (`head`, `spouse`, `children`)
- local counterparties (`liege`, `clergy`, `nobles`)
- an empty `relationships` array

It then materializes directed edges through `ensureRelationshipEdge` for:

- `head -> liege`
- `liege -> head`
- `head -> clergy`
- `clergy -> head`
- `head -> each local noble`
- `each local noble -> head`

No differentiated scores are assigned at this stage. Every seeded edge starts from the shared relationship baseline.

### 2. `relationshipEngine` defines a single flat baseline for every new edge

`src/sim/domains/people/relationshipEngine.ts` currently hard-codes:

- `allegiance: 50`
- `respect: 50`
- `threat: 20`

`ensureRelationshipEdge` always creates missing edges at exactly that baseline, and `driftRelationshipTowardBaseline` also pulls existing edges back toward the same shared values.

### 3. `ensurePeopleFirst` establishes the known-house registry baseline

`src/sim/peopleFirst.ts` creates and/or preserves:

- `h_player` for the player household
- `kinship_edges` for the player household spouse and parent links
- deterministic `h_noble_##` house records for legacy local nobles that would otherwise exist only as persons

The local noble house baseline is intentionally thin:

- default `tier: "Knight"`
- default `holdings_count: 1`
- `head_id` set to the noble person
- no seeded spouse or child graph unless it already exists elsewhere

### 4. `ensureExternalHousesSeed_v0_2_8` seeds T1 external houses, kinship, and a parish institution

`src/sim/worldgen.ts` is the only world-init surface that expands beyond the player house and local noble stubs. It deterministically seeds:

- `h_ext_01..h_ext_##` external houses
- house `tier` chosen from `Knight | Baron | Count`
- deterministic `holdings_count`
- external heads, optional spouses, and children
- `spouse_of` and `parent_of` kinship edges for those external households
- a minimal local parish institution (`i_parish_player_local`) with `type: "parish"`

It also ensures one reciprocal relationship pair between the player head and each external house head:

- `player head -> external head`
- `external head -> player head`

These edges are also created through `ensureRelationshipEdge`, so they inherit the same flat `50/50/20` baseline.

## Identified baselines

### Relationship score baseline

The current T0 relationship baseline is uniform:

- liege, clergy, local nobles, and external house heads all start from `50 allegiance / 50 respect / 20 threat`
- no seeded edge currently varies by actor type, tier, kinship, prior patronage, or geography
- no seeded edge currently exists between church institutions and the player house
- no seeded edge currently exists between the liege/clergy and the external house graph

### Known-house baseline

The current known-house baseline is partially present:

- `h_player` is fully established
- `h_noble_##` gives legacy local nobles deterministic house membership, but only as single-head shells
- `h_ext_##` provides a real T1 house graph with deterministic spouse and child structure
- T1 kinship exists for external houses via worldgen, which satisfies part of the scope-lock requirement that kinship exists for T0 and T1 houses

### Church baseline

The current church baseline is split across two different concepts:

- `locals.clergy` is a person counterparty with reciprocal `head <-> clergy` relationship edges at `50/50/20`
- `i_parish_player_local` is a minimal institution record used for Tier0 visibility

Current parish limits:

- `priest_person_id` is `null`
- no relationship edge is seeded to the parish institution
- no institution-holder linkage exists between `locals.clergy` and the parish institution
- the church is therefore visible as both a person and an institution, but not yet socially unified

## Gaps against the locked v0.3 model

### Gap 1. World init does not satisfy the non-uniform relationship lock

`docs/releases/v0.3_SCOPE_LOCK.md` says the world starts with non-uniform seeded relationship edges and scores. Current init does not do that. It seeds only uniform `50/50/20` edges and lets drift preserve that same center.

### Gap 2. Relationship-driven grants are not actually driven by seeded liege relationships

`docs/releases/v0.3_FISCAL_SPINE_PACKET.md` says liege grants should strongly depend on the seeded liege relationship score. The current grant path in `src/sim/phases/phase_prospects.ts` does not read the liege relationship at all:

- grant availability is gated by arrears only
- grant amount is derived from arrears pressure only
- the predicted relationship effect is a fixed delta applied after acceptance

This means seeded liege affinity currently has no effect on whether a grant appears, how large it is, or how costly it is to take.

### Gap 3. Church obligations and offerings do not yet have a social baseline strong enough for enforcement design

The fiscal spine expects church obligations, offerings, and enforcement to operate through meaningful counterparties. Today:

- the clergy person has a flat baseline edge
- the parish institution exists only as a minimal Tier0 actor shell
- there is no seeded institution-holder relationship model

That is enough for visibility scaffolding, but not enough for clergy placement, church-facing obligations, or institution-sensitive enforcement behavior.

### Gap 4. Known-house coverage is asymmetric

External houses receive a seeded family graph and T1 kinship relevance, but local noble houses remain shallow single-head shells. That asymmetry matters for later dynasty, succession, marriage, claims, and office mechanics because only part of the non-player house set begins with household depth.

## Existing evidence in tests and fixtures

- `tests/sim/tiering_worldgen.test.ts` confirms deterministic external-house seeding, Tier1 candidate presence, T1 kinship scaffolding, and Tier0 parish visibility.
- `tests/v0234_dev_b_patch.test.ts` confirms current grants are generated from arrears pressure and apply a fixed liege-to-head relationship delta on acceptance.
- `tests/fixtures/v0.1.0_state_fixture.json` already carries the same flat `50/50/20` starter relationships, which shows the uniform baseline is inherited behavior rather than a recent regression.

## Audit conclusion

The repo already has deterministic seeding for:

- the player household
- local counterparties
- local noble house shells
- T1 external houses with kinship
- a minimal local parish institution

The missing piece is not structural seeding. The missing piece is differentiated social meaning:

- relationship scores are still uniform at world start
- church person and church institution baselines are not yet unified
- grant and obligation mechanics do not yet consume seeded social state in the way the locked `v0.3` model expects

That leaves `V03-R0-005-T01` complete as an audit baseline and identifies the follow-on design/implementation pressure for deterministic non-uniform relationship seeding.
