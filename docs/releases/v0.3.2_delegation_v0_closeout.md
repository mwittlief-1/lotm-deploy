## Scope

This closeout records the accepted `v0.3.2` delegation baseline after
`T01` through `T05`. It supersedes the opening audit as the current
release-facing summary of what delegation now guarantees, what remains
intentionally bounded, and what later office, agenda, and portfolio work
may assume without recomputing court-domain logic.

## Accepted task sequence

- `T01` audited the current court-budget consumers and identified which
  surfaces were valid delegation candidates for `v0.3.2`.
- `T02` defined the canonical court delegation registry seam and the
  efficiency-only effect contract.
- `T03` wired delegated settlement hooks for liege gifts and church
  offerings, and introduced the first bounded maintenance scaffold.
- `T04` wired delegated marriage scouting through the people-domain
  marriage path with explicit deterministic budget rules.
- `T05` exposed ordered delegation summaries in bounded experience
  snapshots so downstream readers can consume them directly.

## Locked `v0.3.2` delegation rules

### Delegation is a deterministic efficiency layer

The accepted `v0.3.2` delegation baseline now assumes:

- delegation is stored in the court-owned registry at
  `state.house.court_delegation_registry`
- delegation summaries surface through `court_delegation_view_v0`
- delegation effects are explicit numeric modifiers, not probabilistic
  rolls or hidden quality variance
- action ordering remains fixed as `gift_liege`, `offering_church`,
  `marriage_scout`, `maintenance`

### Gifts and offerings delegate through canonical settlement writers

The runtime now supports delegated execution for:

- `liege_gift`
- `church_offering`

Those actions still resolve through the economy-owned settlement helper and
ledger receipt path. Delegation may adjust:

- applied settlement amount
- explicit court-budget cost

It does not bypass the canonical receipt writer or invent a parallel coin
mutation path.

### Maintenance now has a bounded execution seam

`v0.3.2` did not start with an active maintenance mechanic. This epic
introduced the first bounded maintenance scaffold so follow-on work has a
canonical place to apply deterministic upkeep efficiencies and emit
`expense.maintenance` receipts through the coin ledger.

### External scouting can delegate, but it still costs something

Marriage scouting now reads the delegation registry, but the accepted rule
is intentionally narrow:

- delegated scouting may reduce its court-budget cost
- delegated scouting still costs at least `1` court decision
- delegated scouting does not change candidate ordering, offer count, RNG
  stream usage, or inbound marriage handling

That keeps delegation from erasing the strategic cost of external social
action.

## Accepted snapshot outputs

Bounded experience outputs now expose:

- `court_delegation_view`

The view includes:

- fixed `action_keys`
- `active_action_keys`
- ordered action summaries with flattened effect metadata

Bounded snapshot consumers no longer need to parse the raw registry or
recompute modifier meaning from court-domain helpers.

## Explicit `v0.3` non-goals

The accepted delegation baseline intentionally does **not** include:

- autonomous court AI or agenda execution
- automatic handling of inbound marriage acceptance or rejection
- delegation of ordinary `church_due` or `liege_due` settlements
- office-holder staffing, retainer assignment, or service-record logic
- hidden variance, efficiency rolls, or personality-driven delegation
- UI-layer delegation controls in this lane

Those remain future backlog scope, not missing pieces inside this epic.

## Handoff to later tranches

Follow-on work may now treat the following as locked inputs:

- delegation state lives in a court-owned registry with stable action order
- gifts, offerings, scouting, and maintenance all have explicit delegation
  seams
- bounded snapshots surface ordered delegation summaries directly

Follow-on work should not assume the following already exist:

- office or retainer assignment that activates delegation automatically
- multi-action agenda planning beyond the current explicit decision hooks
- broader energy-system rewrites that consume the delegation energy fields
- portfolio UI behavior that already renders the new delegation view

That leaves later office, pre-agenda, and experience work with a stable
delegation contract while preserving explicit room for richer court
automation in later releases.
