## Core doctrine

The player is not omniscient. Knowledge must respect source truth, confidence, provenance, visibility, and succession/context limits.

Proof artifacts are evidence only and are distinct from player-facing explanation.

## Knowledge focus areas

- lineage tracing;
- confidence rails;
- event receipts;
- player-facing “why did this happen?”;
- debug/export distinction;
- dossiers;
- correspondence;
- office-based knowledge;
- succession knowledge shift/loss;
- false or stale information in later versions.

## Confidence rails

Core confidence vocabulary:

- Known;
- Likely;
- Possible;
- Unknown/Unverified;
- Rumored;
- Stale.

SP-010 ratifies this confidence/provenance vocabulary for field planning. It does not authorize UI integration, schema promotion, read-model source-truth behavior, or hidden-truth exposure.

## Receipts

Material changes should preserve:

- source/cause;
- affected actor/entity;
- authority basis;
- resource/relationship/state effect;
- timestamp/turn context;
- confidence/source label;
- player-facing explanation;
- debug/proof link where applicable.

## Stop rules

Codex must not satisfy player-facing legibility by pointing only to debug output, and must not treat receipts/proof reports as source truth.
