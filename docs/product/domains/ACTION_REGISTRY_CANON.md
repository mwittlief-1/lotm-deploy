## Doctrine

The Action Registry is the catalog of canonical state-changing processes in *Lords of the Manor*. Registry actions are not one-to-one UI buttons, and they are not the CourtOS capacity model.

An action row may be invoked by:

- player choice;
- NPC intent;
- institutional process;
- crisis trigger;
- standing directive;
- delegated assignment;
- automatic world process.

## Domains

The registry includes at least these domains:

- Household / Dynasty;
- Marriage / Alliance;
- Succession / Tenure;
- Estate / Manor;
- Fiscal / Obligations;
- Court / Liege / Politics;
- Church / Religious;
- Military / Readiness / Service;
- Local Community / Labor / Order;
- Justice / Crime / Coercion;
- Council / Assembly / Governance;
- Knowledge-Increasing Actions.

Military Readiness and Law / Justice / Accusation are domains/subdomains, not new core action families by themselves.

## Core family discipline

Future rows should map to existing abstract families where possible. Split rows should remain split when they create different gates, receipts, risks, actors, or consequences.

Accepted split examples:

- pay / defer / refuse;
- propose / accept / reject / counter;
- appoint / remove;
- summon / attend / refuse;
- serve personally / send contingent / pay substitute / refuse service;
- appease / suppress / mediate;
- petition / grant / recognize.

## Semantic flags

Registry rows may carry flags such as:

- pressure-only;
- ordinary + pressure hybrid;
- setup/assignment;
- likely standing-adjacent;
- persistent capacity edge;
- standing coverage link;
- crisis/posture activation;
- knowledge-increasing;
- relationship-impacting;
- receipt-required.

## Stop rules

Codex must not:

- treat registry rows as UI buttons;
- implement live A/R/T effects from action rows;
- implement live marriage, claims, succession, obligations, law, or coercion from hooks alone;
- promote inferred registry fields to canonical runtime schema without review;
- reclassify Candidate/Held rows as implemented scope.
