# v0.3 Refactor Charter — Phase Pipeline + Category Domains
**Last Updated:** 2026-03-23  
**Owner:** Integrator / Build Engineer

## Purpose
Create stable code seams so `v0.3` can run in parallel workstreams without turning the repo into merge hell or invalidating the determinism baseline.

## Success Criteria
- `src/sim/turn.ts` is reduced to a thin fixed-order orchestrator.
- New phase modules live under `src/sim/phases/`.
- Domain ownership is explicit under `src/sim/domains/`.
- Relationship and coin writes are centralized behind owning APIs.
- Repo guidance exists in-repo for branch discipline, file ownership, and duplicate-file handling.
- Future lane work can proceed without multiple branches touching the same orchestrator hotspots.

## Non-Goals
- No big-bang rewrite to pure patch composition across every phase.
- No gameplay redesign hidden inside refactor PRs.
- No broad archive purge before active/canonical files are clearly defined.

## Architecture Call
Use two layers:

1. Phase pipeline
   - Owns execution order only.
   - Lives under `src/sim/phases/`.
   - Called by `src/sim/turn.ts`.
2. Category domains
   - Own domain meaning, write rules, registries, and tests.
   - Live under `src/sim/domains/`.
   - Are called from phases; they do not own turn order.

Rule: phases own ordering; domains own meaning.

## Canonical Phase Order
1. `phase_demography`
2. `phase_marriage`
3. `phase_consumption`
4. `phase_obligations`
5. `phase_events`
6. `phase_succession`

This is the target order for `v0.3` seam carving. The current implementation may temporarily route legacy helpers through wrappers until extraction is complete.

## Domain Ownership Targets
- `people`: kinship, households, marriage lifecycle, claims, succession inputs
- `economy`: ledger, obligations, receipts, portfolio accounting, pricing constants
- `court`: delegation scaffolds, roles structure, pacing data
- `world`: topology graph, adjacency, distance bands, geography-derived modifiers
- `realm`: church and political-pressure scaffolds
- `ai`: policy hooks, evidence typing, belief registries
- `experience`: read models and view projections only

## Tranche Order
### Tranche 0 — Repo Rails
- Add in-repo guardrails, codemap, and branch strategy.
- Establish phase/domain directory scaffolds.
- Mark canonical file policy for duplicate-heavy areas.

### Tranche 1 — Behavior-Preserving Phase Extraction
- Move logic out of `src/sim/turn.ts` into `src/sim/phases/*`.
- Keep execution order fixed.
- Avoid semantic changes.

### Tranche 2 — Centralized Write APIs
- Route relationship writes through a dedicated engine.
- Prepare ledger-centric coin writes as the economy seam.

### Tranche 3 — Bounded Context Extraction
- Move marriage into a single owned context.
- Start separating economy and court responsibilities.

### Tranche 4 — UI and Reporting Split
- Break `src/App.tsx` into panels and read models.
- Keep sim writes out of UI code.

## Branching Model
- Preserve `codex/v0.2final` as the stabilization line.
- Use `codex/v0.3-refactor-kickoff` as the integrator branch.
- Cut short-lived lane branches from the kickoff branch:
  - `codex/v0.3-lane-engine-core`
  - `codex/v0.3-lane-social-mechanics`
  - `codex/v0.3-lane-ui-experience`
  - `codex/v0.3-lane-economy-fiscal`
  - `codex/v0.3-lane-world-topology` (blocked until `V03-XMAP-001`)
  - `codex/v0.3-lane-tooling-qa`
- Rebase/merge lane branches only after the integrator branch lands the prerequisite seam for that lane.

## Acceptance Standard
A tranche is ready only when:
- canonical files are clear,
- gates still pass,
- no unplanned golden drift has been introduced,
- and the next lane can work without editing the same hotspot file.
