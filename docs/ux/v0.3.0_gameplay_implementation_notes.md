# LoM UX Implementation Notes — v0.3.0 Gameplay Shell

**Epic:** `V03-R0-004`  
**Closeout task:** `V03-R0-004-T06`  
**Scope:** summarize what the UI lane shipped for the v0.3.0 gameplay shell, record what stayed deferred, and leave a playtest-facing handoff.

---

## 1. Shipped in v0.3.0

### T01 — audit and canonical homes
- `docs/ux/v0.3.0_gameplay_field_homes_audit.md` remains the canonical audit and dedupe map for the gameplay shell.
- The audit conclusion held: the shell needed re-homing and re-weighting of existing facts, not new gameplay data families.

### T02 — locked shell hierarchy
- The gameplay screen now renders in the audited single-column order.
- Sticky headline chips now keep food, coin, and unrest visible without repeating those totals across body cards.
- The relationship drawer no longer competes with the primary gameplay cards and stays in the debug tier.

### T03 — detail and debug shell
- Household roster and house-log detail moved into a reusable modal sheet.
- Raw diagnostics moved into a dedicated debug accordion so audits remain accessible without dominating the main reading flow.

### T04 — explanation routing
- `Explain Changes` now opens a receipts explainer modal.
- Grouped and raw receipt modes are both available.
- Food, coin, and unrest chips route into focused detail views inside the same explainer surface.

### T05 — final chrome and timing pass
- The gameplay shell now uses a lightweight manuscript treatment: parchment surfaces, serif display typography, and deterministic two-letter sigils.
- Timing microcopy now explicitly separates the resolved chronicle above from the next-turn planning surface below.
- No new art asset pipeline or UI dependency burden was introduced.

---

## 2. Current canonical gameplay shell

The gameplay shell in v0.3.0 should now be read in this order:

1. frame chrome with chronicle timing labels
2. sticky resource chips
3. council agenda
4. diff ledger with `Explain Changes`
5. manor state
6. turn report
7. prospects
8. known houses
9. intel
10. events
11. decisions
12. debug accordion

This order is intentional:
- top = what changed and what matters now
- middle = detail and interpretation
- bottom = planning controls and audit-only surfaces

---

## 3. Preserved debug surfaces

The following remain intentionally preserved for replay audits and balancing work:
- Run Log screen and export actions
- Relationship Drawer
- consumption breakdown details
- unrest breakdown details
- prospects log detail

They are still part of the supported v0.3.0 workflow, but they are now explicitly secondary to the gameplay shell.

---

## 4. Deferred after v0.3.0

These ideas were identified during the audit but were not part of the shipped v0.3.0 shell:
- a richer identity strip with ruler, heir, spouse, and energy as a first-class top-line block
- dedicated detail modals for prospects, known houses, intel, and events
- deeper debug-route cleanup beyond the accordion move already shipped
- any new gameplay mechanic, new fact family, or new sim-owned UI contract

These should stay deferred unless they are scheduled as new backlog tasks.

---

## 5. Playtest alignment notes

Playtesters should specifically verify:
- whether the sticky chips and diff ledger make the top-of-screen story legible without scrolling
- whether `Resolved last 3 years` versus `Set next turn` is clear on a first read
- whether `Explain Changes` is discoverable from both the diff ledger and the chips
- whether grouped versus raw receipts feels useful for both normal play and debug review
- whether the debug accordion still feels easy to find when needed

Suggested prompt for internal playtests:

> Can a player explain what already happened, what they are deciding next, and where to open deeper evidence without being coached through the layout?
