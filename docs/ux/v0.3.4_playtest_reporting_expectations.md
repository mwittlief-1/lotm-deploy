# v0.3.4 Playtest Reporting Expectations

**Scope:** define the bug-report template, KPI placeholder conventions, and per-packet reporting expectations that sit on top of the `V03-R4-003-T02` receipt-bundle contract.

## 1. Canonical reporting files

The checked-in reporting templates for this pass are:

- bug report template: `qa_artifacts/playtest_ops/v0.3.4/bug_report_template.md`
- KPI placeholder template: `qa_artifacts/playtest_ops/v0.3.4/kpi_placeholders.json`

When a tester assembles a real packet, those templates should be copied into the packet root with these stable names:

- KPI snapshot: `kpi_snapshot.json`
- bug reports: `bug_report_<NN>_<short_slug>.md`

Use zero-padded bug-report numbers starting at `01`.

## 2. Bug-report expectations

Create one bug report file per distinct issue. Do not combine clarity, balance, and technical issues into one catch-all note.

Each bug report should capture:

- the exact `packet_id`
- `scenario_id`, `policy`, and `seed`
- the replay hash or replay summary reference
- the surface where the issue was first seen
- whether the issue is a `bug`, `clarity`, `balance_signal`, or `ops_gap`
- the shortest possible expected-versus-observed comparison
- the exact packet artifacts reviewed while filing the note

Severity should use this stable ladder:

- `blocker`: the packet or UI flow cannot support review
- `major`: the issue materially changes interpretation or hides critical evidence
- `minor`: the issue is real but still leaves the review usable

## 3. KPI placeholder conventions

`kpi_snapshot.json` is not a scored dashboard yet. It is a structured placeholder that lets later playtest passes compare packet completeness and evidence legibility without inventing new field names every round.

Fill rules:

- leave a field as `null` when the reviewer did not measure it
- use `false` only when the reviewer checked the condition and it failed
- increment the triage counters after the packet review is complete
- set `packet_ready_for_review` to `true` only when the required bundle artifacts and at least one review pass are present

The placeholder focuses on four groups:

- artifact completeness
- export discoverability
- reporting legibility
- handoff readiness

## 4. Reporter workflow

1. Start from the receipt bundle root defined in `docs/ux/v0.3.4_playtest_receipt_bundle_conventions.md`.
2. Copy `qa_artifacts/playtest_ops/v0.3.4/kpi_placeholders.json` into the packet root as `kpi_snapshot.json`.
3. Fill the artifact completeness and discoverability fields before filing issue notes.
4. Copy `qa_artifacts/playtest_ops/v0.3.4/bug_report_template.md` into the packet root once per issue using `bug_report_<NN>_<short_slug>.md`.
5. Update the KPI counters after all issue files are written.
6. Keep the packet, KPI snapshot, and bug reports together so a reviewer can read the evidence without reconstructing filenames by hand.

## 5. Current limits

This task standardizes filenames and fields only. It does not add automatic issue filing, automatic KPI calculation, or a new gameplay export flow.

Later work should reuse these filenames and keys rather than introducing a second report template or a second KPI schema for the same `v0.3.4` playtest packet.
