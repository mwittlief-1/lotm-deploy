# v0.3.4 Playtest Receipt Bundle Conventions

**Scope:** lock the naming, artifact, and seed-pack rules for the `V03-R4-003` playtest-ops pass without pretending the gameplay shell already has a one-click packet export.

## 1. Canonical contract

The current contract is intentionally split between a typed UI seam and a checked-in seed pack:

- typed packet seam: `src/ui/playtestOpsPacket.ts`
- seed pack manifest: `qa_artifacts/playtest_ops/v0.3.4/receipt_bundle_seed_pack.json`

The release label for this packet is `v0.3.4`, but the live runtime still exports `app_version: v0.2.9` inside the run summary JSON. That mismatch is expected on this branch state and should be preserved in the packet rather than renamed away.

Use these stable names whenever a tester assembles or shares a receipt bundle:

- archive name: `lotm_v0.3.4_playtest_receipt_bundle_<scenario_id>_<policy>_<seed>.zip`
- repo capture root: `qa_artifacts/playtest_ops/v0.3.4/receipt_bundles/<scenario_id>/<policy>/<seed>/`

Those names are the new canonical packet convention for the `V03-R4-003` chain.

## 2. Required artifacts

The current shell can export only the two JSON files directly. The rest of the packet is still a manual capture convention until later tasks improve the hooks.

| Artifact | Exact filename or relpath | Current source | Required | Purpose |
| --- | --- | --- | --- | --- |
| Run summary export | `run_summary_<seed>.json` | Decisions footer or debug accordion export buttons | yes | Fast playtest triage and high-signal summary of the resolved run |
| Full run export | `run_export_<seed>.json` | Decisions footer or debug accordion export buttons | yes | Raw run evidence for replay, debugging, and deeper investigation |
| Turn report notes | `turn_report_notes.md` | Turn Report card | yes | Preserve the readable chronicle before the bundle drops into raw JSON |
| Grouped receipt notes | `receipts_grouped_notes.md` | Receipts viewer modal in grouped mode | yes | Capture the player-facing evidence path for coin, food, unrest, and counterparties |
| Raw receipt notes | `receipts_raw_notes.md` | Receipts viewer modal in raw mode | optional | Record phase-by-phase follow-up when grouped evidence is not enough |
| Replay batch reference | `qa_artifacts/seed_replay/v0.2.9/batch/turns_15/summary.json` | checked-in QA artifact | yes | Anchor the packet to the accepted deterministic replay hash |

For now, `turn_report_notes.md`, `receipts_grouped_notes.md`, and `receipts_raw_notes.md` are manual notes files. They are placeholders for human-captured observations, not new UI exports.

## 3. Seed-pack instructions

The authoritative scenario list now lives in `qa_artifacts/playtest_ops/v0.3.4/receipt_bundle_seed_pack.json`.

That seed pack is derived from the accepted replay batch summary at `qa_artifacts/seed_replay/v0.2.9/batch/turns_15/summary.json`, which currently carries canonical hash `4d630db7f2cf8f56da8dee8661e478355e18d6ba662d0141ca58a58837781e64`.

Use the seed-pack scenarios in this order:

1. `baseline_low_pressure_prudent` for the cleanest reference packet and least noisy chronicle review.
2. `arrears_pressure_builder` for overdue obligations, unrest growth, and export-vs-reporting comparisons.
3. `relationship_edges_builder` for counterparty and receipt-group review where follow-up evidence matters.
4. `weather_shortage_builder` for a high-pressure packet that stresses shortages, unrest, and raw evidence flow.

Each scenario records:

- the exact `seed`
- the required `policy`
- the replay artifact path already produced by the canonical batch
- the key surfaces a tester should inspect before assembling the packet

## 4. Playtester flow

1. Start from the scenario entry in `qa_artifacts/playtest_ops/v0.3.4/receipt_bundle_seed_pack.json`.
2. Use the listed `seed` and `policy` when recreating the run, or use the listed replay artifact path when reviewing the already-generated deterministic run.
3. Export `run_summary_<seed>.json` and `run_export_<seed>.json` from the gameplay shell.
4. Copy the resolved chronicle into `turn_report_notes.md`.
5. Capture grouped receipt observations into `receipts_grouped_notes.md`.
6. Add `receipts_raw_notes.md` only when the grouped view is not sufficient to explain the issue or evidence chain.
7. Keep the packet under `qa_artifacts/playtest_ops/v0.3.4/receipt_bundles/<scenario_id>/<policy>/<seed>/` until it is zipped or handed off.
8. Include the replay summary reference or at minimum the canonical replay hash `4d630db7f2cf8f56da8dee8661e478355e18d6ba662d0141ca58a58837781e64` in the handoff notes.

## 5. Current limits

This task does not add a new gameplay export button, a bug-report template, or KPI placeholders. It only locks the packet naming and the seed-pack instructions around the surfaces that already exist.

Later tasks in `V03-R4-003` should build on this contract rather than inventing another packet name, another seed list, or another artifact root.
