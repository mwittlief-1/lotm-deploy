## Scope

This closeout records the accepted `v0.3.3` court agenda baseline after
`T01` through `T05`. It replaces the earlier audit as the current summary of
which source families now feed the agenda contract, how the UI consumes those
items, and which boundaries still remain outside this epic.

## Accepted task sequence

- `T01` inventoried the current mixed agenda builder and mapped the strongest
  explainer homes for obligations, prospects, offices, and portfolio outliers.
- `T02` defined the canonical agenda registry schema, typed source tags, and
  source mappings.
- `T03` populated the registry deterministically from obligations, prospects,
  offices, and bounded portfolio outliers.
- `T04` replaced the legacy mixed shortlist with registry-backed agenda stubs
  and added bounded what-mattered notes plus direct anchors to the existing
  summary surfaces.
- `T05` added determinism coverage and published this closeout so later court
  energy work can treat the agenda baseline as locked.

## Locked agenda rules

### Source selection is now domain-owned

The accepted agenda selection no longer lives in the UI shell as a set of
ad hoc manor-pressure heuristics. Instead, the court domain now emits agenda
items from the locked source families:

- obligations
- prospects
- offices
- portfolio outliers

The UI now consumes the already-selected registry items and does not rebuild
the shortlist from unrelated food, labor, unrest, or succession heuristics.

### Conflicts and truncation are deterministic

The registry now resolves the main collision cases in a stable way:

- obligation enforcement wins over generic arrears or due rows for the same
  counterparty
- expiring prospects win over generic grant or marriage rows for the same
  prospect
- only one bounded portfolio outlier row is surfaced per manor at a time
- the visible agenda window is always a deterministic top slice of the ordered
  registry

That gives downstream UI and content work a predictable shortlist without
recomputing source precedence.

### UI stubs are now source-safe

The court agenda card now renders registry-backed stubs with:

- stable ids
- source-safe titles and context lines
- bounded what-mattered notes
- anchors to the existing explainer homes

The accepted anchor mapping is:

- obligations -> obligations panel
- prospects -> prospects panel
- offices -> household surface
- portfolio outliers -> portfolio totals and outliers surface

## Accepted non-goals

This epic intentionally does **not** add:

- new turn orchestration in `src/sim/turn.ts`
- new agenda decision mechanics beyond the existing card and CTA shell
- content-authored narrative text for each agenda row family
- energy or AI systems consuming agenda state directly

Those remain later scope, not unfinished work in this baseline.
