# LoM UX Audit — v0.3.3 Experience Content Inventory

**Task:** `V03-R3-007-T01`  
**Scope:** inventory the current content slots already shaping obligations, gifts, offerings, grants, marriage outcomes, arrears stages, and dispossession language; map where that copy lives today; and document the gaps before the content-template pass rewires current UI surfaces.  
**Constraint:** inventory only. No new simulation logic and no player-facing wording changes in this task.

---

## 1. Locked content families

The locked `v0.3.3` content pass needs one inventory across these families:

- obligations settlement
- gifts and offerings outcomes
- grants received or denied
- marriage accept or reject
- arrears stage warnings
- dispossession warnings

The current shell already exposes all of those topics somewhere, but the copy is split across three homes:

1. UI-owned view-model helpers in `src/ui/playScreenObligations.ts`
2. App-level copy strings in `src/App.tsx`
3. isolated surface text inside panels such as `ReceiptsViewerPanel.tsx` and `ManorStatePanel.tsx`

`src/content/experienceContent.ts` is now the canonical slot inventory for this pass.

## 3. Existing hard-coded or placeholder copy by surface

### Obligations, gifts, and offerings

The strongest current content already exists, but it still lives in UI code:

- `COUNTERPARTY_META` in `src/ui/playScreenObligations.ts` owns liege and church helper text
- `gestureRelationshipSummary()` in `src/ui/playScreenObligations.ts` owns gift and offering leverage phrasing
- `resolvedPressureSummary()` and `responsePressureSummary()` in `src/ui/playScreenObligations.ts` own this-turn versus next-turn obligation language
- `COURT_DECISION_BUDGET_ACTION_COPY` in `src/ui/playScreenCourtBudget.ts` repeats the gift and offering detail text
- `ReceiptsViewerPanel.tsx` adds its own counterparty-path explainer copy on top

This means the v0.3.1 obligations legibility work already established the right vocabulary, but that vocabulary is still embedded in render-adjacent code instead of a content registry.

### Grants and marriage

Grant and marriage copy is more centralized, but it is still generic:

- `src/App.tsx` owns the confirm titles and bodies for grant and marriage prospects
- `src/App.tsx` also owns the accept or reject toast strings
- `ProspectsPanel.tsx` renders those strings, plus the current grant helper and standing-risk note
- marriage aftermath text such as `marriageToast_line1` and the spouse or court-size follow-up still lives in `src/App.tsx`

So these families already have a copy source, but not one typed around the locked v0.3.3 outcome categories.

### Arrears and dispossession

Arrears messaging is partially present:

- `Stage 1 active` and `Pressure clear` come from `enforcementStageLabel()` in `src/ui/playScreenObligations.ts`
- the resolved and response summaries describe carried arrears and what the player can do next

The missing piece is the rest of the ladder:

- there is no shared stage-two wording for tangible bite
- there is no stage-three warning string for dispossession danger before game over
- the only current dispossession wording is:
  - the unrest threshold tip in `src/ui/panels/ManorStatePanel.tsx`
  - the end-state label in `src/App.tsx`

That leaves the shell able to explain failure after it lands, but not yet able to warn through one stable fiscal content family as pressure rises.

---

## 4. Gaps against the UX spine

1. The shell does not yet have one content registry for the fiscal and relationship outcome spine.
2. Gifts and offerings share counterparty meaning with obligations, but their wording is still duplicated between budget and explainer surfaces.
3. Grant and marriage copy is centralized at the app layer, but it is not yet organized as typed content slots that later playtest or content work can extend safely.
4. The arrears ladder stops at the v0.3.1 stage-one baseline in UI-authored text.
5. Dispossession warnings do not currently exist as a pre-trigger player-facing content slot.
