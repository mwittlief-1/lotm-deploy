### Portfolio outliers

Current state:

- portfolio totals, bounded outlier rows, selected-manor detail, and evidence-scope labels already ship

Gap:

- outliers are still a separate holdings context, not a court agenda source
- no typed bridge exists from an outlier flag into a deterministic agenda stub

## 5. Current mismatch to preserve and fix later

The shell already has the information needed for the court agenda pass, but it is split across two layers:

1. A UI-owned mixed agenda builder in `playScreenModel.ts`
2. Stronger, more specific summary surfaces elsewhere in the shell

That creates the current mismatch:

- the agenda card is simpler than the summary surfaces behind it
- the office and portfolio systems are richer than the agenda knows
- typed source identity exists in several bounded seams, but not yet in one agenda contract

The practical consequence is that the agenda currently answers:

- "what should I look at next?"

but it still does so with incomplete court semantics. It does not yet answer:

- which locked court family produced this item
- whether the follow-up belongs to obligations, prospects, offices, or portfolio outliers
- which already-shipped summary surface should be treated as the canonical explainer for that agenda row

---

## 6. Task-ready conclusions

1. The current agenda list is still a legacy mixed shortlist. Only `obligations` and `prospects` from the locked `v0.3.3` source list are represented directly today.
2. The shell already has stable explainer homes for all four locked source families: obligations cards and receipts, prospects panel, household roster/succession summaries for office-adjacent facts, and portfolio totals/outlier rows.
3. Office and delegation work is mechanically ready but UI-indirect. The roster can show officer labels, yet there is still no dedicated office summary or agenda bridge.
4. Portfolio outliers already have a strong bounded summary surface, but they remain outside the agenda path entirely.
5. `V03-R3-003-T02` should define a typed agenda source contract that maps each locked family onto one deterministic, snapshot-safe source tag instead of recomputing those meanings inside `src/ui`.

This audit should be treated as the canonical inventory for the `V03-R3-003` agenda contract pass.
