# LoM UX Implementation Notes — v0.3.3 Experience Content Spine

**Scope:** summarize the shipped v0.3.3 content-template pass for obligations, offerings, grants, marriage, arrears stages, and dispossession warnings; record which live UI surfaces now consume the shared content registry; and leave a stable handoff for playtest ops.

---

## 1. What shipped

### T01 — content slot inventory

- `docs/ux/v0.3.3_experience_content_inventory.md` remains the canonical inventory of the locked content families and the original gap map.
- `src/content/experienceContent.ts` became the typed registry for the full v0.3.3 content pass.

### T02 — obligations, gifts, and offerings

- Liege and church settlement copy now shares one template family.
- Gift and offering outcome wording now uses one counterparty-aware path instead of repeated UI-local strings.

### T03 — grant and marriage outcomes

- Grant confirm and accept-or-reject toast copy now comes from one typed grant template family.
- Marriage confirm, dowry-aware accept copy, reject copy, and immediate household aftermath wording now come from one typed marriage family.

### T04 — arrears stages and pre-trigger warnings

- The arrears ladder now names stage-two tangible bite and stage-three dispossession danger through one shared template path.
- Pre-trigger dispossession danger wording now appears before the actual end-state lands.

### T05 — live surface wiring

- `PlayScreen.tsx` now routes grant and marriage confirms, toasts, and the dispossession game-over label through shared content helpers instead of local string assembly.
- `ProspectsPanel.tsx` now reads the grant helper and standing-risk note from the grant template family.
- `ManorStatePanel.tsx` now reads the unrest-threshold dispossession tip from the shared dispossession content slot.

---

## 2. Canonical content spine

The v0.3.3 content spine now resolves through these homes:

- `src/content/experienceContent.ts`
  - source of truth for typed experience content slots and rendering helpers
- `src/ui/playScreenExperienceCopy.ts`
  - UI seam that maps live prospects and game-over flows onto the shared content registry
- `src/ui/playScreenObligations.ts`
  - obligations contract now consumes shared arrears, settlement, and response wording
- `src/ui/panels/ProspectsPanel.tsx`
  - grant helper and standing-risk copy
- `src/ui/panels/PlayScreen.tsx`
  - prospect confirmations, toasts, and the dispossession game-over banner
- `src/ui/panels/ManorStatePanel.tsx`
  - unrest-threshold dispossession tip

This is the canonical v0.3.3 UI content wiring unless a later backlog task explicitly reopens the experience copy spine.

---

## 3. Playtest handoff

Playtest and UX follow-on work can now assume:

- obligations, gifts, and offerings share one stable copy path
- grant and marriage outcome wording is typed and deterministic
- arrears ladder messaging and dispossession warnings are aligned from pre-trigger warning through end-state label
- current gameplay surfaces reference the shared content registry rather than ad hoc local strings

If later playtest ops need copy tuning, they should start in `src/content/experienceContent.ts` and verify the affected live surfaces listed above before changing any UI-local fallback text.
