# v0.3.3 AI Rail Packet

**Last Updated:** 2026-04-08
**Owner:** Engine / AI lane
**Reference Audit:** `docs/releases/v0.3.3_AI_RAIL_BASELINE_AUDIT.md`

This document is the authoritative `v0.3.3` closeout for `V03-R3-006`.
It locks the belief payload seam, the replay-safe evidence emitters, and
the hidden debug packet that later UI/content work can inspect without
changing gameplay authority.

## Locked baseline

- `v0.3.3` AI remains rails-only: evidence capture, belief storage, and
  bounded `npcPolicyScore(...)` hooks.
- No hidden inference, archetype behavior, or autonomous policy layer is
  active in `v0.3.3`.
- `src/sim/turn.ts` still owns the canonical preview/resolution evidence
  transport into `phase_results_v0[*].evidence_events_v0` and the
  `recordBeliefEvidence(...)` pass.
- Domain-owned emitters may now author runtime-only evidence at the seam
  where the meaning is known, but that debug evidence does not become the
  source of gameplay truth.

## Canonical surface inventory

| Surface | Status | Runtime meaning | Notes |
| --- | --- | --- | --- |
| `belief_registry_v0` | Active internal memory rail | Stores bounded subject-scoped observations used by the existing AI rails. | Still the durable backing store; no schema break was introduced. |
| `belief_payload_v1` | Active read-only subject view | Normalizes stored observations into Known / Likely / Possible states per subject. | Used by policy summaries and debug reads. |
| `belief_payload_registry_v1` | Active read-only registry view | Wraps all known subject payloads in a deterministic registry packet. | Read-only; does not mutate state when missing beliefs are inspected. |
| `domain_evidence_log_v1` | Active runtime-only debug surface | Holds deterministic current-turn evidence emitted directly from marriage, obligations, and bounded grant flows. | Resets on turn advance and stays outside replay-visible receipts and phase evidence. |
| `policy_hook_debug_v1` | Active read-only hook contract | Exposes current hook scales and the explicit rule that no intel means no bonus. | Keeps marriage/prospect bonuses inspectable without widening behavior. |
| `ai_rail_debug_packet_v1` | Active hidden bounded snapshot packet | Bundles belief payloads, current runtime evidence, and policy-hook metadata for diagnostics. | Non-enumerable on bounded snapshots, so the serialized contract remains stable. |

## Accepted emitter coverage

`V03-R3-006-T03` moved representative AI evidence capture to the domain
edge for the flows already owned by this lane:

- Marriage resolution:
  - scouting
  - inbound budget blocks
  - reject-all resolution
  - invalid selection
  - acceptance blocks
  - acceptance success
- Obligations:
  - settlement applied / blocked reasons
  - carry-to-arrears decisions
  - stage-one enforcement outcomes
- Grant preview:
  - grant eligibility open / blocked
  - bounded grant prospect available / unavailable

These events are intentionally diagnostic rails. They do not replace the
canonical receipt, note, or phase-result outputs used by the live sim.

## Hidden debug boundary

- `boundedSnapshot(...)` now exposes a hidden `ai_rail_debug_packet`
  property alongside the existing hidden `beliefs` payload.
- The packet is read-only by contract and remains non-enumerable, so
  `JSON.stringify(snapshot)` does not widen the bounded export surface.
- The packet is intentionally composed from safe read helpers:
  belief-payload reads do not initialize or rewrite `state.beliefs`, and
  evidence reads do not create persistent runtime entries when no current
  evidence exists.

## Neutral policy contract

- `npcPolicyScore(...)` still has only two active hooks in `v0.3.3`:
  `marriage_offer` and `prospect`.
- Both hooks remain bounded belief-backed bonuses only.
- With no subject-scoped belief intel, both hooks are neutral and return
  the base score unchanged.
- The shipped debug contract exposes the live tuning scales directly so
  reviewers can see when a hook is enabled, reduced, or zeroed without
  inferring hidden AI logic from outcomes.

## Handoff

- Later UI/content work should prefer the hidden `ai_rail_debug_packet`
  over reconstructing AI meaning from raw `beliefs` plus phase-local
  evidence separately.
- Future AI activation work should widen behavior only through explicit
  new contracts, not by letting debug-only evidence become gameplay
  authority implicitly.
- If future work changes hook math, payload shape, or emitted domain
  events intentionally, it should update this packet, the task run logs,
  and the regression anchors together so the review delta stays legible.
